## Specs
S1. User: "Revisa y pasemos a la autenticación". Implement the backend authentication slice against the already applied report schema, not Laravel's scaffold tables.
S2. User: "Preparemos primero el backend y después el front". No authentication screens, dashboard, frontend changes, public registration, recovery workflow, clinical CRUD or opportunistic schema/dependency changes.
S3. User selected: "Sí, comando privado (recomendado)" to the question "¿Incluimos un comando privado para crear el primer administrador junto con la autenticación? No pegues contraseñas acá." Include a manually invoked initial-administrator command with hidden password/confirmation, no default credentials or automatic creation. Do not implement CU03 account-management UI/API.
S4. Report CU01: "El usuario introduce su nombre de usuario o correo electrónico y su contraseña." Check password hash, active account, role and permissions before establishing a valid session; rejected access must not create an authenticated session. Report E2: "Credenciales incorrectas o cuenta no habilitada: se rechaza el acceso con un mensaje que no revele innecesariamente la existencia o el estado de la cuenta." Report E3: "Error al consultar los datos o establecer la sesión: se informa que no fue posible completar el acceso, sin exponer detalles internos."
S5. Report CU02: "La sesión queda invalidada. Para realizar nuevas operaciones protegidas, el usuario debe autenticarse nuevamente." Expired sessions cannot authorize protected operations; do not falsely confirm an uncertain logout.
S6. Report: "Una cuenta inactiva no podrá iniciar sesión ni continuar realizando operaciones protegidas". Protect web mutations with CSRF, regenerate session on successful login, and never expose password hashes/credentials or invented permission grants.
